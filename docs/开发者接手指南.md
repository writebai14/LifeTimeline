# 开发者接手指南

## 1. 项目当前状态（2026-08-18）
- 核心流程已可用：按天记录时间块、查看历史媒体、导入导出文本、日期切换。
- 新增了“记录活跃度日历”（格子 + 颜色深浅），放在标题栏按钮内的弹出层，默认展示最近 14 周。
- 左侧时间轴样式已强化分类可视化，不同 tag 的块区分明显。
- `days` 存储已启用严格服务端校验、原子写入和按日历史版本，支持 API 查询及恢复。

## 2. 代码地图（先读这些文件）
- `src/App.tsx`：应用入口状态管理；日期切换、保存逻辑、活跃度弹层接入。
- `src/DayView.tsx`：单日主界面；时间轴渲染、时间块编辑入口、导入导出。
- `src/DayView.css`：时间轴视觉样式（重点看 `.timeline-*` 与 `.block-card*`）。
- `src/ContributionCalendar.tsx`：格子日历逻辑（时间范围、分级阈值、点击跳转）。
- `src/api.ts` + `server/index.js`：前后端数据接口。
- `server/app.js`：Express 应用与路由，可独立创建实例进行 HTTP 测试。
- `server/day-validation.js`：日期、`Day / Block / Media` 结构与引用完整性校验。
- `server/day-store.js`：原子写入、历史快照、保留策略与恢复逻辑。
- `src/types.ts`：数据模型定义（`Day` / `Block` / `Media`）。

## 3. 数据与存储
- 日志数据：`data/days/YYYY-MM-DD.json`
- 历史版本：`data/history/days/YYYY-MM-DD/<version>.json`，默认每个日期保留 30 份；用 `LIFETIMELINE_DAY_HISTORY_LIMIT` 调整。
- 旧媒体文件：`data/media/*`。当前不再提供图片上传和删除入口；已有日记中的媒体可查看和下载，`Day.media` 数据仍保留以兼容旧记录。
- 开发环境代理：
  - 前端 `5173`
  - 后端 `3001`
  - 代理配置见 `vite.config.ts`

### 单日数据安全约束

- `PUT /api/days/:date` 仅接受真实存在的 `YYYY-MM-DD`，且请求体 `date` 必须与路径一致。
- 顶层和嵌套对象均拒绝未知字段；必填数组、字符串、布尔值、时间、ISO 时间戳和枚举均做类型/格式校验。
- block/media ID 必须唯一，关联 ID 必须能在同一份 day 数据中找到。
- 写入顺序为：校验 → 原子写入历史快照 → 原子替换正式文件 → 清理超限旧版本。
- 历史查询和恢复接口见 README；读取正式文件或历史版本时也会再次校验结构。

## 4. 活跃度日历维护说明
- 分数函数在 `src/App.tsx` 的 `dayRichnessScore`。
- 颜色分级在 `src/ContributionCalendar.tsx` 的 `LEVEL_COLORS` 与 `scoreThresholds`。
- 交互入口在标题栏 `.header-actions`，组件默认显示 `weeksToShow=14`。
- 如要改“什么算丰富”：优先只改 `dayRichnessScore`，保持 UI 组件纯展示。

## 5. 后续开发建议（低风险高收益）
- 增加“活跃度计算说明”悬浮提示，解释颜色含义与分值来源。
- 增加“仅显示有记录日期”筛选，减少空白格密度。
- 增加“周/月统计总览”，与格子图联动。

## 6. 协作约定（建议执行）
- 每次功能修改后，必须同步更新：
  - `docs/CHANGELOG.md`（写清日期、功能、影响文件）
  - 若涉及架构/入口变化，同步更新本指南
- PR 模板建议固定三段：
  - 变更目标
  - 影响范围（文件）
  - 验证方式（命令 + 人工检查点）
- 后端数据层变更至少运行 `npm test`；全项目交付前运行 `npm run build`。
