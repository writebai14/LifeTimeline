# 开发者接手指南

## 架构（2026-10-16）

前端为 React/Vite，服务端为 Express 5 / TypeScript，数据库为 PostgreSQL 17。生产构建分别输出到 `dist/` 和 `build/`，应用同源提供静态页面和 API。开发环境只代理 `/api`。

`server/app.ts` 组装路由与访问控制；`auth.ts` 负责密码和会话；`days.ts` 负责日志事务与历史；`imports.ts` 负责预览、执行、重试；`db.ts` 负责连接、事务和版本迁移。共享的数据模型及校验位于 `shared/domain.ts`。

## API 契约

- `POST /api/auth/login`：用户名、密码；返回用户及 CSRF 值，Cookie 保存随机会话标识。后续写入请求要求匹配 `Origin` 与 `X-CSRF-Token`。
- `GET /api/auth/me`、`POST /api/auth/logout`、`POST /api/auth/password`：当前身份、退出、修改密码。修改密码后需要重新登录。
- `/api/admin/users`：管理员列表和创建；`PATCH /:id` 接收 `active`；`POST /:id/reset-password` 接收临时密码。不能停用自己或最后一个启用的管理员。
- `GET /api/days/:date` 返回 `{day, revision}`；未记录日期返回 `{day:null, revision:0}`。`PUT` 接收 `{day,expectedRevision}`，不接受客户端指定用户。冲突返回 409。
- `GET /api/days/:date/history` 返回版本列表；`GET /history/:version` 返回正文；`POST /history/:version/restore` 接收 `expectedRevision`，恢复本身增加版本。
- `GET /api/stats` 返回每日覆盖分钟数、字数、完成和有记录标记；不返回完整日记正文。`GET /api/days` 仅返回日期列表。
- `POST /api/imports/preview` 接收 `{files:[{name,content}]}`，`content` 为单日 JSON 原文；返回批次 ID 和校验结果。`GET /:id` 查询，`POST /:id/execute` 接收 `{selected:[索引]}`。首次执行冻结选择，重试只能使用同一选择。
- `GET /api/export` 流式输出当前用户的单日 JSON ZIP，基于一致性数据库快照，不包含历史。

所有业务查询必须使用会话中的用户 ID。当前日期数据按 `(user_id,date)` 唯一，事务通过日期锁串行化并检查客户端版本号；每次有效变化同时写当前记录和历史，默认最多 30 份。导入按日期提交数据和结果状态，重试跳过已完成项。导入预览 1 小时失效，结果保留到过期后 7 天。

新模型移除了图片字段。只有导入适配器接受并丢弃旧 `media`、`linkedMediaIds`，将 `from_media` 转为 `manual`；正常日志写入拒绝这些旧字段。旧文字来源 `from_quick_note` 继续兼容。

## 前端约束

`SessionGate` 控制登录、改密和会话过期。退出和切换账户清空应用状态。过期登录遮罩保留当前页面，重新登录同一账户后可处理草稿。

保存失败不得显示成“空日志”，不得悄悄重读覆盖草稿；409 只能让用户保留草稿后主动重新加载。导入或恢复前要求先处理未保存内容。统计通过摘要接口加载，不逐日请求全部内容。

## 验证与维护

`npm run build` 检查前后端并构建。`TEST_DATABASE_URL=... npm test` 执行独立 PostgreSQL 测试，数据库名称必须以 `_test` 结尾；测试会清空其中数据。`npm run test:e2e` 验证真实浏览器流程，需要先构建及安装浏览器。

修改接口、schema 或访问规则时，更新测试、CHANGELOG 和部署文档。数据库迁移仅追加，不修改已应用文件。部署、管理员初始化、备份与回退见 [DEPLOYMENT.md](DEPLOYMENT.md)。
